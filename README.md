# Parapharmacy data quality (dbt + Snowflake)
 
> 🚧 **Work in progress.** Version 1 is being built in November–December 2026. Sections marked *TODO* are not written yet.
 
A dbt project that checks whether a retail chain's daily stock export can be trusted for pricing and stock decisions, and shows where the chain should fix problems first.
 
**Scenario (fictional):** 15 parapharmacy outlets in Belgium sell near-expiry health products at a discount. Each outlet exports a daily stock snapshot, with one row per stock lot. The data is **synthetic**, generated by a script in this repo. No real company or customer data is used.

## Data
 
- `data/raw/inventory_snapshots.csv`: daily snapshots for 1–30 October 2026, 15 outlets, with deliberate quality issues.
- `seeds/branches.csv`, `seeds/product_families.csv`: reference tables.
- `scripts/generate_data.py`: regenerates the data. It uses a fixed random seed, so it always produces the same files.
- `docs/data_dictionary.md`: column descriptions.
## Data-quality checks
 
Some tests **warn on purpose**. They measure problems in the raw export rather than stop the build. The staging versions of the same checks fail the build if the cleaning doesn't work.
 
| Check | Where | Severity | Why |
|---|---|---|---|
| One row per lot per day | staging | warn | Measures duplicates in the export |
| `pack_unit` has an accepted value | source | warn | Measures spelling variants in the raw data |
| `pack_unit` has an accepted value | staging | error | Proves the normalisation worked |
| `pack_unit`, `date_type` not null | source | warn | Measures missing values in the export |

## How to reproduce
 
You need a Snowflake account and Python 3.
 
1. **Clone the repo and install dbt**
```
git clone https://github.com/BeSciBianca/parapharmacy-data-quality-dbt
cd parapharmacy-data-quality-dbt
python -m venv .venv
source .venv/bin/activate
python -m pip install dbt-core dbt-snowflake
```
2. **Create the raw table in Snowflake.** Run `setup/01_create_raw.sql`. It creates the `RAW` schema, a file format, the stage `RAW_FILES` and the all-text table `INVENTORY_SNAPSHOTS`.
   *TODO: does the script also create the database `PARAPHARMACY_DQ`? If not, add that step.*
3. **Load the data.** Upload `data/raw/inventory_snapshots.csv` to the stage `RAW_FILES` (in Snowsight: Data → Databases → stage → upload), then run the `COPY INTO` statement.
   *TODO: check the menu path and say whether `COPY INTO` is in the setup script.*
4. **Create your dbt profile.** dbt reads connection details from `~/.dbt/profiles.yml`, which is never committed. Add a profile named `parapharmacy_dq` that connects to Snowflake. See the [dbt Snowflake setup docs](https://docs.getdbt.com/docs/core/connect-data-platform/snowflake-setup) for the fields, including key-pair authentication. Then check the connection:
```
dbt debug
```
5. **Install packages and build everything** (seeds, models and tests):
```
dbt deps
dbt build
```
   The build should finish with some **warnings** (see *Data-quality checks*) and no errors.
